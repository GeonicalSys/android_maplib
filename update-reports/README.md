# Карточки обновлений

Срезы отчёта и письма лежат только в монорепозитории `lisa`, каталог
`docs/update-reports/`. Здесь — карточки доработок `maplib`.

Файл: `update-reports/entries/<id>.md`. Префикс id: `maplib-`.
Имя файла совпадает с id.

```yaml
---
id: maplib-20261008-short-slug
area: Мобильное приложение
kind: internal
at: 2026-10-08T16:40:00+02:00
title: Что изменилось в работе, одной фразой
why: Зачем это нужно тому, кто пользуется ЛИСА
---
```

`kind` — `user` или `internal`. Оба входят во внутренний отчёт.

Карточку добавлять в том же PR, что и доработку. Не отмечать её как уже
вошедшую в отчёт и не класть сюда файлы среза. Полная процедура —
`docs/update-reports/README.md` в `lisa`.

## Автоматическая проверка карточек

Проверка схемы всех карточек и покрытия текущих изменений:

```powershell
py -3.13 -B tools/check_update_reports.py
```

Новая карточка обязана содержать `covers`: список **точных** путей файлов от
корня своего Git-репозитория. Нужен новый ID на самостоятельную доработку.
Изменённая старая карточка не закрывает новые исходники. Проверяются также
тесты, скрипты, hooks и workflow; отсутствующий файл после удаления тоже
нужно указать. Несвязанная карточка в большом PR не закрывает остальные пути.
Шаблоны `*`, `**`, относительные переходы и повторные пути запрещены.

```yaml
covers:
  - plugins/example/main.py
  - plugins/example/tests/test_main.py
```

Примеры путей выше относятся к настольной системе; в каждом репозитории
нужно указать его собственные файлы. Метаданные `covers` не переносятся
в текст письма заказчику. Исторические карточки без этого поля допустимы;
для новых оно обязательно. Для восполнения истории можно добавить
`source_commits` со списком полных SHA исходных изменений.

Чисто текстовые Markdown-правки и данные реестров в каталогах `docs`
не требуют новой карточки. Для остальных служебных исключений создать
**новый** файл `exemptions/<имя-задачи>.yaml` рядом с `entries`:

```yaml
category: version
reason: Поднята только версия перед выпуском без изменения поведения.
paths:
  - plugins/example/metadata.txt
```

Допустимые категории: `version`, `collect`, `documentation`, `no-behavior`.
Причина должна объяснять конкретное исключение, а список содержит только
файлы текущей задачи. Старое исключение нельзя повторно использовать для
новой доработки. Обоснованность исключения и соответствие смысла карточки
коду остаются предметом review: механическая проверка не понимает весь код.

Один раз на каждом клоне установить зависимость PyYAML из
`tools/requirements-update-reports.txt` в используемый Python и выполнить:

```powershell
py -3.13 tools/check_update_reports.py --install-hook
```

Это локально задаёт `core.hooksPath=.githooks`. Чужие hooks автоматически
не перезаписываются. После установки обычный `git push` проверяет **дерево
отправляемого коммита**, поэтому незакоммиченная карточка push не разрешит.
Пропущенная/битая история Git останавливает проверку; сначала нужен fetch.
Hooks являются локальным контролем и могут быть обойдены `--no-verify`;
такой обход запрещён командным договором. Новый клон требует установки.

Для CI/проверки готовой головы: `--head HEAD`; отдельно для сборки реестра:
`--schema-only`; для машинного результата: `--json`. Основа сравнения —
общий предок с основной веткой из `tools/update-report-policy.json`;
при проверке другого стека её можно явно указать через `--base <ref>`.

Проверки самого контроля:

```powershell
py -3.13 -B -m unittest discover -s tools -p test_check_update_reports.py -v
```
